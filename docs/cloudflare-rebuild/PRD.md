# MeetScript — external Codex portfolio PRD

Status: specification, not a deployed or verified application. Build custom MeetScript code in an external Codex environment, not on this box or through the Tropos factory. Read architecture.md, DESIGN.md, CODEX-HANDOFF.md and REQUIREMENTS-CHECKLIST.md together. SCOPE-UPDATE.md records the final scope decisions; bundled kit recipes are subordinate reference material.

## 1. Product and binding scope
A verified workspace member pastes a Google Meet URL, confirms recording disclosure and requests an immediate join. A visibly named `MeetScript — recording` bot waits for admission, captures received audio, and produces a timestamped transcript, useful minutes and editable actions. Users can search and ask cited questions across meetings they may access. This is a polished portfolio application, not a billing SaaS.

- Custom MeetScript implementation; no Goshen repository, code or service dependency.
- Cloudflare-only application and capture runtime: Workers, Durable Objects, Cloudflare Containers, D1, private R2, Queues/Workflows, Workers AI and Vectorize. No managed capture provider or external VM fallback.
- Google Meet pasted URL only; no Google Calendar OAuth, calendar connection, meeting invitation ingestion or scheduled/recurring joins in core scope. App Google sign-in is optional identity-only OAuth, not Calendar access or a bot Google identity.
- Only authenticated, verified, active workspace members may authorize joins. Possession of a Meet URL, an email sender address or a public demo session is insufficient.
- Audio-only recording/transcription. No video, screen recording, screenshots as product artifacts, live voice participation or hidden capture. Camera and microphone stay off.
- No billing, checkout, paid plans, subscriptions, trials or entitlement gates. Operational quotas protect infrastructure, not monetization.
- An application-managed mailbox is optional deferred work, recommended for deferral but not explicitly approved or cancelled by the user. It is not core acceptance, navigation or an implementation dependency; any later scope requires a separate decision. Auth transactional email remains in the kit.
- English first. No Zoom/Teams, enterprise SSO, autonomous external actions or production certification claims.

## 2. Mandatory feasibility gate (G0)
Before presenting capture as working or committing to the full integration, deploy a minimal custom Playwright/Chromium + virtual audio + FFmpeg runner to Cloudflare Containers under a Durable Object. Verify current resources, networking, browser sandbox/support, lifecycle APIs and limits from official sources. Use an explicitly consented test Meet, visible bot identity, actual host admission and actual received speech. Produce playable audio in private R2 and verify duration, audibility and clean stop. Record container image digest, environment, deployment/version, timestamps, consent record and private evidence references. Test termination, interrupted upload and partial recovery.

A local browser demo, mock media, successful port health, silent audio file or Alook caption scraping is not a pass. Alook PR35/41 show local browser/caption orchestration, not audio capture on Cloudflare Containers. If admission requires authentication, return `authentication_required`; if denied, return `admission_denied`. Never collect Google passwords, copy profiles, solve CAPTCHA or bypass platform/security restrictions. If the gate fails, report the exact blocker and keep the capture feature explicitly unavailable; no hidden hosting/provider substitution. Offline UI/test work may continue with conspicuously labelled fixtures, not integration claims.

## 3. Functional requirements
### FR-01 Identity, workspace and authorization
Use the portable auth/session contracts with email OTP verification; optional Google OIDC and GitHub login only if equivalently verified identity is established. Provider identity alone is not proof of verified email: validate the provider claim or require OTP. Codes expire, are single-use and rate-limited; production never returns them. Access tokens stay in memory; rotating refresh cookies are Secure/HttpOnly with appropriate SameSite, CSRF/origin protection and revocation. Turnstile protects abuse-prone auth endpoints.

Create a workspace with owner/admin/member roles. Workspace enrollment uses an expiring single-use token or owner-controlled membership flow, not automatic membership from an email domain. These are membership invitations, never meeting invitation scheduling. Owner transfer precedes owner removal. Every request rechecks active membership and session revocation. Creator-private meetings by default; explicit workspace sharing or meeting grants may broaden access only within that workspace. Owner/admin manage workspace lifecycle; private content still requires explicit meeting access (no implicit admin transcript bypass). Verified members with access may join their own new meeting, stop their capture, and edit allowed content; workspace admins may emergency-stop a session for safety without gaining content access.

### FR-02 Paste and join
Join dialog: HTTPS Meet URL, optional title, timezone, maximum duration, private/workspace visibility, recording disclosure and affirmative consent/authority acknowledgement. Strictly accept `https://meet.google.com/<valid-meeting-code>` only, reject credentials, arbitrary hosts/paths/ports and redirects; parse and normalize server-side, not by substring. Do not store unnecessary tracking queries. Recheck membership, consent version, quota and cancellation just before dispatch. Reserve duration atomically. Deduplicate retries and active sessions for the same workspace + normalized Meet code; do not expose other workspaces' activity.

Show queued, starting, joining, waiting-for-admission, recording, stopping, processing, ready, partial, failed, denied and cancelled states. An auth-required failure is explicit, not an endless spinner. Authorized stop/cancel works during any active phase and is idempotent. Recording begins only after admission and consent policy checks. Disclose the bot and recording to participants; host admission alone is not proof of every participant's consent. Owner approves jurisdiction-appropriate disclosure and stop procedure before real use. Never infer consent from silence.

### FR-03 Audio and transcript
Upload bounded independently playable numbered chunks to private R2 with checksums and a durable manifest. Provide authorized seeking/playback and transcript navigation to timestamps. Verify audio availability rather than animating fake waveforms. Workers AI transcribes real audio with validated input limits and pinned model/configuration. Preserve original segments and versioned corrections. Speaker names are not guaranteed by mixed Meet audio; use Unknown speaker when uncertain and do not fabricate diarization. Missing chunks or recorder loss yield explicit gaps and partial output, never a complete badge. Support authorized TXT/VTT transcript and Markdown minutes export.

### FR-04 Minutes and actions
Schema-validated minutes contain summary, topics, decisions, unresolved questions and action items. Every factual item cites source transcript version, segment IDs and time ranges. Unsupported sections say no evidence found. Actions have title, optional owner, optional due date, status, source citations and needs-review state. Unknown owners/dates remain null; resolve relative dates only with meeting date/timezone and preserve source wording. Members with edit permission confirm, edit, assign and complete actions with version conflict handling. Regeneration creates a new draft; it never overwrites reviewed actions. No automatic outbound task email or agent mutation.

### FR-05 Search and cited chat
Search transcript text and filter meeting lists by date, status and visibility. Persistent conversations support a current meeting, selected meetings or authorized workspace scope. Vectorize retrieval and every source chip are authorized server-side at request time. Show clickable title/timecode citations opening exact segments and audio where retained. Do not leak inaccessible titles, counts or snippet text. Abstain with “I could not find that in the selected meetings.” if evidence is insufficient. Treat transcripts and retrieved text as untrusted data, never system instructions. Chat is read-only in core scope. Stream/cancel/retry with incomplete output labelled; index lag shows indexing, not false readiness.

### FR-06 Dashboard, actions and accessibility
Overview prioritizes active sessions, recent minutes, failures needing attention and open actions; no calendar/upcoming schedule. Meeting lists and action lists paginate with stable cursors. Actions filter by assignee, due date and status. Follow DESIGN.md for complete routes, tokens, responsive layouts, loading/empty/error/permission states, keyboard behavior and screenshots. Avoid decorative dashboard metrics or fabricated usage/live signals.

### FR-07 Privacy and deletion
Private media by default. Proposed operational retention: audio 30 days; transcripts/minutes/actions 90 days; related chat evidence no longer than source retention. Owner can shorten retention before use. Explain consent, data processing, retention, deletion and backup limitations in privacy/recording copy; no unsupported compliance claims. Account/workspace export and deletion require authority and ownership-transfer handling. Delete immediately tombstones and blocks reads/jobs, stops active capture, then removes R2 chunks/exports, D1 content, Vectorize vectors and dependent chat answers/citations. Track pending, complete and failed cleanup; retry and surface failure. Retain only minimal non-content audit facts as disclosed. Restores must replay deletion tombstones before reopening access.

### FR-08 Operational budgets and reliability
Proposed pilot defaults, to validate at G0: max 120 minutes per session, 10-minute admission timeout, 2 concurrent sessions per workspace, 600 captured minutes per workspace per rolling 30 days, and a configurable global concurrency ceiling initially 2. These are non-billing limits with no upgrade CTA. Rate-limit join/chat/export; cap upload size, model tokens and retries. Show remaining/reserved usage and duration before join. Reserve maximum duration then settle actual captured duration once; release unused allocation on terminal outcomes. A conservative reservation may remain while an uncertain session is reconciled. Never silently restart a recording after termination or membership revocation. Member revocation before dispatch cancels; during capture stops that member's active session and revokes ingestion credentials.

## 4. Acceptance and delivery
REQUIREMENTS-CHECKLIST.md maps each requirement to evidence; unchecked means not yet implemented/verified. A clean checkout must pass pinned install, strict typecheck, lint, unit/Workers integration, migrations, browser/axe and security checks via a documented `npm run verify`. Test cross-tenant access, revoked membership, idempotent dispatch, quota races, container crash/restart, stale events, model failures, injection, citation validation and deletion races.

Real preview acceptance requires G0 plus audio → Workers AI transcript → cited minutes → Vectorize-backed answer → action edit → forbidden access from another workspace → deletion/read-back. Production promotion requires owner approval, isolated resources and actual smoke validation, not a successful deploy command alone. Fixtures are test-only and clearly labelled. Report credential/policy blocks honestly. Performance targets, not measured promises: API p95 <500ms excluding AI/media; first chat token <3s on typical context; process 60 minutes within 10 minutes after capture ends. Measure and report conditions rather than fabricating results.

## 5. Owner inputs and non-goals
Owner supplies authorized Cloudflare access/limits/budget, final domains, authentication mail transport and verified sender if using email OTP, optional identity OAuth clients, approved retention/disclosure and a consenting test meeting. Secrets enter CI/Codex secret storage only. Domain suggestions from earlier drafts (`meetscript.divineweb.co`, `meetscript-preview.divineweb.co`) remain unapproved examples. No provider purchase, production DNS changes or deployment is authorized by this document alone.
