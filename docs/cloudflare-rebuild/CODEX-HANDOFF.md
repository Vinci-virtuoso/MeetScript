## Binding implementation brief
Build custom MeetScript code, no Goshen repository/service. Verified workspace members paste Google Meet URLs and explicitly authorize an immediate, disclosed join by `MeetScript — recording`. Audio-only capture/transcription; summary, decisions, unresolved questions and actions; tenant-scoped Vectorize retrieval and cited chat. All application/capture runtime is Cloudflare: custom Playwright/Chromium/virtual-audio/FFmpeg Container controlled by a Durable Object; Workers, D1, R2, Queues/Workflows and Workers AI. No managed capture, VM fallback, hidden bot, security bypass, video, billing or Google Calendar access. App identity OAuth does not provide bot authentication. If Meet requires authentication, fail explicitly.

Mailbox: optional deferred, not core acceptance; deferral was recommended but not explicitly approved or cancelled. Do not implement meeting email invitations, scheduled/recurring joins or mailbox navigation as a hidden dependency. Auth transactional email is retained. No pricing, checkout or subscriptions; quotas are operational only.

## Execution phases and exit evidence
1. **Inventory and safety.** Create a non-destructive rebuild branch from the actual current baseline when authorized. Inventory source/migrations/deployment resources. Preserve existing work; report exposed credentials for owner rotation without printing them. Scan secrets. Review kit licenses and package compatibility. Produce standalone commands, not host/factory assumptions.
2. **G0 first: actual Cloudflare capture feasibility.** Minimal preview Container/DO runner with visible bot, mic/camera off, virtual audio + FFmpeg. Validate current runtime/limits/readiness/networking. Join a real explicitly consented Meet after host admission, capture received speech, upload and listen to private playable R2 audio, stop/clean up. Test hard termination, partial upload recovery and lifecycle without browser UI traffic. Save redacted evidence references and exact environment/image version. Local mocks, caption scraping, silent media and a green health endpoint do not pass. If blocked, report exact error and mark G0 blocked; no automatic provider/VM substitute. Offline design/tests may continue, but no “working integration” claim.
3. **Foundation and isolation.** Port selected scaffold/auth/authz/db/api/email contracts, not product-specific kit logic. Email OTP verified identity and active workspace membership; optional OIDC identity-only. D1 tenant-aware repositories, private meetings, permissions and audit. Test cross-tenant/revoked access and CSRF before adding content endpoints.
4. **Capture lifecycle.** Implement immediate join validation, quota reservations, idempotent dispatch/fenced epochs, consent, stop/cancel, chunk ingestion, heartbeats/deadlines, reconciliation, graceful stop/hard-loss handling and drained rollouts. Recheck membership at dispatch; never silently rejoin after loss.
5. **Processing and privacy.** Real audio → Workers AI STT → versioned transcript → schema-validated cited minutes/actions → embeddings/Vectorize. Add retry/DLQ, bounded jobs, retention/tombstones/deletion, authorized range playback/export, indexing status and unknown-speaker handling. Processing retries never start a bot.
6. **Polished product.** Implement every DESIGN.md route and state, responsive screens, accessible keyboard/dialog/player behavior, persisted edits, read-only cited chat and honest empty/partial/failure states. Label demo fixtures and keep them separate from real workspace data and evidence. No live-looking fake signals.
7. **Validation and preview.** Provide `npm run verify` from clean checkout, lockfile, unit/Workers/migration/browser/axe/security suites and a requirement-to-test report. Deploy isolated preview only when authorized, read back exact bindings/resources/health, run complete real acceptance with two workspaces and consented audio, then deletion/stop and forbidden access checks. Missing secrets/account capacity are blockers, never fabricated passes.
8. **Production readiness, not automatic promotion.** Prepare config/bootstrap, runbooks, observability, drains/rollback/restore tests and least-privilege CI. Production promotion needs explicit owner approval, measured real smoke validation and exact URL/version evidence. A deploy command alone is not validation. Otherwise report “not deployed” with remaining owner setup.
